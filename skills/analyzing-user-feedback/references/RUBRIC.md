# Rubric (Score 1–5)

Score the User Feedback Analysis Pack. Target: **≥ 20/30** overall, with no category below **3** for high-stakes decisions.

## 1) Decision clarity (1–5)
- **1:** No decision; vague “insights” request with no stated outcome or audience.
- **2:** A loose goal exists (“understand feedback”) but no specific decision, deadline, or scope boundary.
- **3:** Decision stated; scope and audience mostly clear; deadline exists but success criteria are soft.
- **4:** Decision + deadline are explicit; success criteria exist but could be sharper; scope boundaries are mostly clear.
- **5:** Decision + deadline + success criteria are explicit; scope boundaries are crisp; “what we'll do differently” is stated.

## 2) Data coverage + sampling rigor (1–5)
- **1:** Single anecdote stream (e.g., 5 hand-picked tickets); no sampling explanation or source inventory.
- **2:** One source documented; sample is convenience-based; no limitations stated.
- **3:** Multiple sources or a documented sample; limitations stated; segment coverage has gaps but they're acknowledged.
- **4:** Clear source inventory; sampling rationale is documented; major segment gaps are identified.
- **5:** Clear inventory + representative sampling with stratification; segment coverage and caveats are explicit; bias from each source is noted.

## 3) Taxonomy/codebook usability (1–5)
- **1:** Tags are unclear, inconsistent, or a generic copy-paste set (bug/feature/UX/other) with no product-specific grounding.
- **2:** Some tags defined but definitions overlap or are ambiguous; no examples provided.
- **3:** Clear definitions; workable tag set; severity scale present; a new tagger could use it with some guidance.
- **4:** Well-defined tags with examples and exclusions; severity + impact scale; two taggers would mostly agree.
- **5:** Codebook enables consistent tagging by any team member; includes/excludes + examples for each tag; supports the decision directly; inter-rater reliability would be high.

## 4) Theme quality + evidence traceability (1–5)
- **1:** Themes are generic (“users are unhappy”) and lack evidence; no quotes or counts.
- **2:** Themes exist but are too numerous (20+) or too broad; evidence is anecdotal (1 quote per theme).
- **3:** Themes have quotes/examples and basic quantification; some segment breakdowns; confidence levels are rough.
- **4:** Themes are specific with multiple supporting quotes; quantified by frequency and severity; segment splits where useful.
- **5:** Themes are specific, well-evidenced (3+ supporting items each), quantified appropriately, split by segment/source, with explicit confidence levels and contradictions noted.

## 5) Actionability of recommendations (1–5)
- **1:** Recommendations are vague (“improve onboarding”) or absent; no prioritization.
- **2:** Some actions listed but not tied to specific themes or evidence; no expected impact.
- **3:** Concrete actions tied to themes; some prioritization; expected impact is directional.
- **4:** Ranked actions with evidence links; time horizons suggested; learning plan for unknowns exists.
- **5:** Ranked actions with owners/time horizons, expected impact (quantified where possible), and a clear learning plan for unknowns; quick wins are separated from strategic bets.

## 6) Durability + loop design (1–5)
- **1:** One-off report with no follow-up plan; insights will be lost within a sprint.
- **2:** Follow-up is mentioned but no cadence, owners, or storage location defined.
- **3:** Basic cadence and storage plan; engineering participation is unclear.
- **4:** Clear cadence + owners + storage; engineering is included; plan to avoid duplicated research.
- **5:** Clear operating model (cadence, owners, engineering participation, escalation path) and a plan to prevent duplicated research; feedback loop connects back to product planning.
